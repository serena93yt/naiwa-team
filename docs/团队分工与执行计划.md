# 团队分工与执行计划

> **目标**：把「80% 半成品」补成「100% 参赛作品」。  
> **作品 = 三块拼图**：① 方案文档（讲清做什么）② 可跑 Demo（证明能做）③ 现场演示（路演 + 答辩）。  
> **现有资产**：`TK运营智能体参赛方案.md`、`tk-agent-demo/`（4 个脚本 + 网页卡片）、`可靠数据源清单.md`、`答辩路演材料.md`。

---

## 一、四人角色总览

| 角色        | 代号 | 能力定位      | 一句话使命            |
| --------- | -- | --------- | ---------------- |
| **设计负责人** | A  | 擅长设计      | 让作品「看起来专业、拿得出手」  |
| **代码负责人** | B  | 擅长代码      | 让作品「能跑、跑得稳、可扩展」  |
| **内容负责人** | C  | 偏新手（可给指令） | 让知识库「真实、可追溯、有料」  |
| **路演负责人** | D  | 表达/统筹     | 让作品「讲得清、答得稳、不翻车」 |

> 注意：A/B/C/D 是代号，请四人根据实际能力对号入座。若有人既是「设计」又是「表达」，可兼任两个角色，但**每个角色必须有唯一的第一负责人**。

## 三、各角色详细任务（含可照抄的启动动作）

### A · 设计负责人

| 任务        | 具体交付物                       | 验收标准              |
| --------- | --------------------------- | ----------------- |
| 产品 UI 视觉稿 | 首页 + 结果页的高保真设计图             | 能看出「这是一个产品」，不是命令行 |
| 参赛 PPT    | 15-20 页路演 PPT               | 每页一个观点，评委 3 秒看懂   |
| 网页美化      | 优化 `index.html`/`risk.html` | 配色统一、有产品名/logo    |
| 封面/海报     | 项目封面图 + 一张演示海报              | 可直接用于提交/现场        |

**A 的第一周启动动作**：

1. 打开 `tk-agent-demo/index.html` 看现状，列出「哪里丑」。
2. 从 `TK运营智能体参赛方案.md` 的第一章「核心场景」里，提炼一句话定位，作为 PPT 第一页。
3. 用 Figma 或 PPT 先画 5 页骨架（封面 / 痛点 / 方案 / Demo 截图位 / 价值），再填内容。

### B · 代码负责人

| 任务    | 具体交付物                                     | 验收标准                 |
| ----- | ----------------------------------------- | -------------------- |
| 批量生成  | `batch_generate.py`（读 Excel → 多产品一键出五国结果） | 输入 5 个产品的表格，跑出 5 组结果 |
| 接热点能力 | 数据接口模块（BibiGPT/Hermes 或爬 TK 标签）           | 能演示「热点 → 选题」这一环      |
| 一键启动  | 打包脚本 / 启动说明                               | 评委面前 10 秒能跑起来        |
| 技术文档  | `技术说明.md`                                 | 代码和方案文档架构对齐（说的和做的一致） |

**B 的第一周启动动作**：

1. 先跑通现有 Demo（`python tk_agent.py`），确保环境 OK。
2. 把「批量生成」作为第一个任务——它最直观、最加分、难度最低。
3. 每完成一个功能，同步更新方案文档第三章「技术架构」，保证一致。

### C · 内容负责人（新手可照抄）

| 任务    | 具体交付物               | 验收标准           |
| ----- | ------------------- | -------------- |
| 市场数据  | 五国 GMV/月活/品类最新数据表   | 每条有来源 + 日期     |
| 禁词/规则 | 扩充后的合规词库（有法条出处）     | 能追溯「这条禁词依据哪条法」 |
| 母语者校对 | 至少印尼语 + 英语两门的话术校对记录 | 有母语者反馈截图/文档    |
| 爆款案例  | 2-3 个真实 TK 东南亚爆款拆解  | 有链接 + 拆解（为什么火） |

**C 的第一周启动动作（照着做即可）**：

1. 打开 `可靠数据源清单.md`，把里面 4 类资料逐条更新到「2025/2026 最新版」。
2. 每查到一条，用这个格式记：`数据 | 数值 | 来源 | 链接 | 日期`。
3. 去 Fiverr / Upwork / 本地留学生群发一句话：「帮我校对 5 条印尼语 TikTok 文案，每条 ¥20」。
4. 在 TikTok 搜「东南亚爆款 + 你的品类」，找 2-3 个案例存下来。

### D · 路演负责人（新手可照抄）

| 任务      | 具体交付物                 | 验收标准            |
| ------- | --------------------- | --------------- |
| 方案终稿    | 润色后的 `TK运营智能体参赛方案.md` | 无错别字、逻辑通顺、数据有出处 |
| 路演串词    | 你本人能自然讲出的定稿           | 不是背稿，是「用自己的话讲」  |
| 答辩 Q\&A | 10-20 个高频问题 + 3 句话答案  | 每个问题 30 秒内答完    |
| 排练 + 统筹 | 排练记录 + 进度看板           | 5 分钟演示不超时、不卡壳   |

**D 的第一周启动动作（照着做即可）**：

1. 通读 `答辩路演材料.md`，用**你自己的话**复述每段（不要背）。
2. 录一遍自己讲，听哪里卡壳，改顺。
3. 列 10 个「评委可能问的问题」，答案控制在 3 句话内。
4. 建一个共享表格/文档，把四人任务列进去，每天更新进度。

### 各角色「一周版」最简任务（缩水版）

**A（设计）一周只做 3 件：** PPT（15 页，命根子）→ 美化 index.html（1 小时）→ 封面图。**砍掉**：高保真 UI、海报。

**B（代码）一周只做 2 件：** 跑通现有 Demo + 写一键启动 README → 修已知 bug。**砍掉**：批量生成、接热点数据。现有 4 个脚本已够演示。

**C（内容）一周只做 3 件：** 查五国市场数据（带来源）→ 补 2-3 条有出处的禁词 → 找 2 个爆款案例。**砍掉**：母语者校对（用「诚实标注 AI 生成」替代）。

**D（路演）一周只做 3 件：** 串词改口语版 → 背熟 10 个答辩问题 → 排练 3 遍掐到 5 分钟内。统筹提交继续由 D 做。

## 五、三条协作铁律（避免翻车）

1. **串行主线别断**：`C 查的数据 → 填给 B 的知识库 → B 跑通 → A 包装 → D 排练`。前一步没完成，后一步会卡。
2. **新手不做技术活**：C/D 负责「查数据、找素材、整理、排练」——这些有明确交付物、不需技术，却是评审要的「数据真实性」。
3. **说做一致**：B 每改一个功能，D 必须同步改方案文档，A 必须同步改 PPT——**别出现「PPT 里说的功能，Demo 里没有」**。
